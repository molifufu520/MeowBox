# MeowBox

> 一个面向个人的**云端加密视频库与流式播放**方案：云盘只存密文，手机随时原画质点播、自由拖动进度条，并支持从多个来源省心地加密入库。

---

## 一、核心目标

1. **云端零明文隐私保护**
   - 视频在上传到云盘之前完成**分块加密**，密钥仅由自己保管。
   - 云盘只能看到密文数据，无法识别视频画面与声音；开启文件名加密后也无法获知片名。
2. **手机端原画质流畅播放**
   - 看视频时电脑可以关机，也不依赖大型自建媒体服务器。
   - 利用云盘的 `HTTP Range`（按字节范围分段下载）能力，点开即可边下边解密播放，拖动进度条只拉取对应区间的数据。
3. **多来源统一加密入库**
   - 统一收口来自 `Telegram`（电报）、`PikPak`（皮克帕克云盘）及其他渠道的视频。
   - 所有来源经加密处理后，以**同一套密文格式**存入云盘；播放端无需关心视频原本来自哪里。

---

## 二、整体架构方向

整个系统按职责拆成**互不耦合的两半**，只要约定好同一套分块加密格式，两部分可以独立演进：

```text
[多渠道视频来源]                  [低配海外服务器：流式入库中转]             [云盘存储]                [手机端]
Telegram / PikPak / 其他  --->   拉取 -> 内存中分块加密 -> 直接上传   --->   Google Drive   --->   按段拉密文 -> 本地解密播放
                                 (不落地大文件、不做高耗能转码)              (仅存密文)            (边收边解 / 预读 / 拖动秒切)
```

### 上半场：入库中转站（低配海外服务器）
- **定位**：复用现有 1 核 1 GB（吉字节）内存的海外服务器，充当轻量的“搬运 + 加密管道”，不影响服务器上原有的网络服务。
- **核心策略**：
  - **流式搬运**：数据边下载、边分块加密、边上传至云盘，避免撑爆小服务器硬盘，同时将内存占用控制在较低水平。
  - **专注加密不转码**：保持原画质，不在低配服务器上运行高负载的视频转码任务。
- **来源接入方向**：
  - `Telegram`（电报）：通过私人机器人转发视频触发后台自动入库。
  - `PikPak`（皮克帕克云盘）：直接对接搬运，加密写入目标云盘后可按需清理旧文件。
  - 其他来源：预留通用直链或上传入口。

### 下半场：手机播放端
- **定位**：面向手机日常观看，专注“点开快、播得顺、拖动不卡”。
- **播放与缓冲优化方向**：
  - **边收边解密**：每收完并校验一个完整加密块就立刻交给播放器，无需等待整段下载完成。
  - **后台前向缓冲**：起播后在后台维持一定时长的提前读取，复用网络连接，减少播放中途转圈。
  - **拖动优先响应**：拖动进度条时若未命中缓存，立刻取消旧区间请求，优先拉取新位置密文。
  - **封装优化（可选）**：对索引位于末尾的 `MP4`（常见视频格式），入库前可无损执行 `faststart`（将索引移至文件开头）以加快起播速度。

## 三、当前技术倾向（初版待进一步细化）

- **目标云盘**：优先使用 `Google Drive`（谷歌云盘，已确认支持 `HTTP Range` 分段读取）。
- **加密格式**：优先评估兼容 `rclone crypt`（开源工具 rclone 的分块加密规范），兼顾“现成工具可用”与“自研客户端可控”；后续视实际开发复杂度决定直接复用还是精简自研。
- **核心开发语言**：倾向使用 `Go`（Go 编程语言）实现流式搬运、分段读取与解密核心逻辑。

---

## 四、分阶段推进路线（Roadmap）

- [ ] **阶段一：最小播放链路验证**
  - 先跑通核心能力：从云盘加密文件按任意字节位置读取、实时解密并喂给本地播放器，验证拖动进度条只消耗少量流量。
- [ ] **阶段二：小服务器流式入库打通**
  - 在海外服务器上跑通第一条自动加密入库通道（优先从最常用的来源开始，如 `Telegram` 或 `PikPak`），确认内存、磁盘和带宽平稳。
- [ ] **阶段三：手机端播放体验完善**
  - 确定手机端方案（对接现成播放器/客户端或自建轻客户端），逐步补齐缓存预读、拖动切流与片库浏览体验。
